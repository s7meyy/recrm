# عقد بيانات رابح

الشكل الموحّد الذي تنتهي إليه كل مصادر الاستخراج، ومنه وحده تقرأ كل المراحل التالية.
هذا العقد هو سبب كون تبديل مصدر البيانات لاحقًا **إضافة موصّل واحد** لا إعادة بناء.

المصدر الرسمي للتعريف: `js/schema.js`.

## الشكل

```js
{
  schema: 1,
  source: 'manual' | 'places' | 'provider',
  capturedAt: '2026-09-15T10:00:00.000Z',
  mapsUrl: 'https://…',
  placeId: '',
  identity: {
    name, category, address, phone, website,
    coords: { lat, lng } | null,
    hours: [],        // ["الأحد: 8ص – 11م", …]
    attributes: [],   // ["توصيل", "مواقف مجانية", …]
    priceLevel: '',
  },
  ratings: {
    average: 4.3 | null,
    count: 1287 | null,
    distribution: { 5, 4, 3, 2, 1 },
  },
  reviews: [ /* انظر أدناه */ ],
  photos: [ { url, caption } ],
  qna: [ { question, answer, date } ],
  popularTimes: [ { day, hours: [{ hour, level }] } ],
  notes: '',          // ملاحظات صاحب التقرير — تُعامَل كبيانات موثوقة
}
```

### التعليق

```js
{
  id: 'R001',        // ثابت، وهو سند كل استنتاج في التقرير
  author: '',
  rating: 1..5 | null,
  date: '',          // كما ورد ("قبل شهرين") أو ISO إن توفّر — لا يُحوَّل
  text: '',
  ownerReply: '',
  language: '',
  likes: null,
}
```

## قواعد مُلزِمة

1. **المعرّفات تُمنَح مرة واحدة** عبر `assignReviewIds` ولا تتغيّر بعدها؛ تغييرها يُبطل السند في تقرير سبق إنتاجه.
2. **التواريخ لا تُحوَّل.** النسبي يبقى نسبيًّا؛ تحويله اختراعُ دقّةٍ ليست في المصدر.
3. **الإحصاءات لا يحسبها نموذج.** `stats()` تحسبها وتُسلَّم جاهزة، والميثاق يأمر النموذج بنقلها كما هي.
4. **`notes` وحدها** هي المدخل المسموح لمعلومة من خارج قوقل، وتُوسَم في الرسالة بأنها من صاحب التقرير.

## ماذا يلزم كل مصدر مستقبلي؟

| المصدر | يملأ | يبقى ناقصًا |
|---|---|---|
| `manual` (اليوم) | كل شيء يدويًّا | لا شيء — لكن بجهد |
| `places` (Google Places API) | `identity` و`ratings` و`photos` و`hours` و`attributes` | التعليقات: خمسة فقط |
| `provider` (مزوّد وسيط) | التعليقات كاملة و`qna` | قد يغيب `popularTimes` |

إضافة مصدر = دالة واحدة تُرجع هذا الشكل. لا شيء بعدها يتغيّر.
